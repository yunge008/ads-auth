## 1. 术语

| 术语 | 定义 |
|---|---|
| **站点池** | 同一站点下所有店铺共享一个达人池。**PH、PH2、PHL = 同一个 PH 池**；其他站点各自一个池。冷却、保护、认领、冲突、TAG 全部按「站点池 + 达人」判定，**不按店铺**。 |
| **达人键** | 站点池 + 达人（`creator_open_id` 优先；没有时用归一化用户名）。 |
| **触达** | BD 主动发出的联系。分两类渠道：①**联盟渠道** = 本系统群发私信、本系统定向邀约、插件群发（三者视为同一渠道）；②**外部渠道** = 社媒、WhatsApp 等通讯软件、TK 账号私信、邮件（需在系统登记，见 §6.1）。 |
| **建联成功**（认领事件） | 以下任一发生，即归属给对应的 BD：①达人**回复**了该 BD 的触达；②达人**申样**且由该 BD **批准**；③该 BD **拿到素材**（建联表登记回收 VID）。 |
| **跟进权**（运营归属） | 谁有权联系该达人、处理其申样、给其发样。本文件说的「归属」默认指跟进权。 |
| **GMV 归属** | 归因引擎按飞书建联表计算的业绩归属，见 §7。 |

## 2. 触达冷却：14 天

- **范围**：同一站点池、同一达人、**联盟渠道内**，两次触达之间至少间隔 14 天，**不分是不是同一个 BD**。
  - 例：9/20 林丽洪群发 abc → 9/21–10/3 任何人（含林丽洪本人）都不能再给 abc 群发或发定向邀约；**10/4 起可以**。
- **跨渠道不设冷却**：外部渠道与联盟渠道之间互不限制。
- **定向邀约与群发同等对待**：都算触达，都只有 14 天冷却。
- **同一会话内的人工沟通不算新触达**：达人回复后的来回聊天不受 14 天限制。（默认，见 §10）
- **自动跟进暂停**：原交接文档 R5（首发 3 天后自动跟进）暂不实现。R4（达人回复前最多 2 条）保留，适用于人工跟进。
- **冷却只防重复触达，本身不产生归属。**
- **被拦截时结果表要写明**：「X月X日 某BD 已触达，Y月Y日起可再发」。

## 3. 认领与保护

### 3.1 未被保护的达人（公共池 / 从未建联）
- 对该站点有权限的在职 BD 都可以触达（受 §2 冷却约束），**谁先建联成功归谁**。
- 例：9/20 林丽洪群发 abc，abc 未回复；10/5（已过 14 天）李汝华给 abc 发定向邀约，abc 回复 → 建联成功，**归李汝华**。

### 3.2 定向计划的 2 个月 ≠ 归属保护期
- 定向计划默认 2 个月结束，这只是**计划有效期**（佣金、样品权益的有效期），不产生归属保护。
- 定向邀约是一次「触达」，只受 §2 的 14 天冷却保护。

### 3.3 保护期：90 天，含第 90 天
- **锚点** = 该达人下列日期中最晚的一个：建联成功日、最近发样日、最近回收 VID 日（申样批准属于建联成功）。
- **计算**：锚点为 D，则 D 到 D+90（**含 D+90**）为保护期，D+91 起回到公共池。
  - 例：1/1 发样，此后无动作 → 4/1（第 90 天）仍受保护，**4/2** 回公共池。
- **续期**：保护期内再发生发样、回收或新的建联成功，锚点更新为新日期。
- 只有回复、之后一直没有发样或回收 → 从回复日起算 90 天后过期。
- **达人的普通回复（只回消息、不发样也不回收）暂不续期**，跟进权和 GMV 归属两层都不续。达人第一次回复仍然算建联成功（取得跟进权、设定锚点），之后的回复不更新锚点。
  - 例：1/1 发样，之后一直只聊天、最后一次回复 3/15 → 跟进权和 GMV 保护都到 4/1，4/2 回公共池。
  - 后续：系统搭建完成后，再评估把「达人回复」纳入续期（届时跟进权与引擎一起改，引擎部分属于 §7 的 B 线改动）。开发时把回复事件完整存下来（会话、时间、对应 BD），为以后纳入续期留好数据。

### 3.4 保护期内其他 BD 的动作
- **联盟渠道**：系统直接拦截，不能群发、不能发定向、不能处理申样。
- **外部渠道 / 飞书登记**：系统拦不住，生成冲突项（§5）。
- 归属 BD 本人同样受 §2 的 14 天冷却约束。

### 3.5 回复对应哪个 BD
同一店铺与同一达人只有**一个会话**，多个 BD 可能先后在里面发过消息。规则：**回复归给回复时间之前、该会话里最近一次触达的 BD。**
- 例：林丽洪 9/20 群发（未回复），李汝华 10/5 发定向卡片，abc 10/8 回复 → 归李汝华。

### 3.6 申样对应哪个 BD
- 申样来自某个定向计划 → 归该计划的发起 BD，由该 BD 批准后即为建联成功。
- 无法判断来源时 → 归申样前最近一次触达的 BD。
- 批准人与上面判出的 BD 不一致 → 冲突项。

## 4. 离职

- 飞书交接表上的日期 = 离职 BD 的**最后工作日 L**。
- L 当天及之前，其达人仍归该 BD；**L+1 起全部进公共池**，按 §3.1 由在职 BD 重新建联认领。
- VID 绑定永久保留原登记人（GMV 侧，不变）。

---

## 5. 冲突

以下情况生成「冲突待判」，**系统只提示，不自动改归属**，由负责人判定。判定结果写入现有人工判定表，参与之后的计算。

| 类型 | 例子 |
|---|---|
| 保护期内他人发样/登记 | abc 在林丽洪保护期内，林乐欣在飞书建联表登记给 abc 寄样 |
| VID 重复登记 | 同一 VID 被两人登记 |
| 跟进权与 GMV 归属不一致 | 系统跟进权归李汝华，飞书建联表的发样登记人是林乐欣（见 §7.4） |
| 同日 / 顺序无法判断 | 两个 BD 同一天建联成功 |
| 跨店铺同站点 | PH2 的 BD 与 PH 的 BD 先后认领同一达人 |
| 外部渠道举证 | BD 凭截图主张外部渠道更早建联成功 |
| 申样批准人不一致 | §3.6 |

通知方式：保护期内他人动作、VID 重复 → 即时用飞书私聊通知双方；其余每日汇总一次。（默认，见 §10）

## 6. 外部渠道与插件

### 6.1 外部渠道建联
- BD 在系统或插件里登记「外部沟通」：渠道、日期、达人、截图（必填）。
- 带截图且达人有回复的登记 → 记为建联成功（来源 = 外部）。如果与他人的跟进权冲突，进冲突待判。
- 公司表要求通过外部渠道开发的达人「在联盟后台发消息留存记录」，系统提示 BD 补发一条联盟私信。

### 6.2 插件（取代灵途AI「达人360」）
- **群发回传**：插件每次群发要分阶段回传，全部写入触达记录，与系统群发同等参与 §2 冷却和 §3 认领。
  - 开始：批次 ID、BD 账号、店铺、计划发送的达人列表
  - 过程：每条一行，含达人昵称、达人 ID/用户名、消息内容、发送时间、发送结果
  - 结束：成功数、失败数、失败原因汇总
- **发送前预检**：插件发送前调用本系统接口，按 §2 / §3.4 剔除不可发的达人。（默认，见 §10）
- **标签展示与标记**：插件在聊天界面的达人列表和达人页面上，按 §8.1 显示每个达人的「归属标签」（上）和「群发标签」（下），并提供群发标签编辑、外部沟通登记入口。**归属标签由系统生成，不可自定义。**
- **插件现有的 14 天跳过逻辑**：插件群发时会自动查看该达人的聊天记录，14 天内有记录就跳过。保留这个逻辑，但它只能看到**当前店铺**的会话，看不到同站点其他店铺（如 PH 与 PH2）和其他 BD 在系统里的触达，也不知道保护期。所以仍需在发送前调用本系统预检，按站点池补齐 §2 冷却和 §3.4 保护期拦截；两者任一判定跳过即跳过。
- 插件账号沿用本系统的登录和权限；禁用账号后插件立即不能用。

## 8. TAG 与视图

### 8.1 达人标签：两类，每个达人上下两行显示，归属标签在上

**① 归属标签（上行，系统生成，不可自定义）**
- 格式：`{BD名}·{后缀}`。BD 名取自发起触达 / 建联的**登录账号**；后缀由后台按本规则计算的归属状态给出，每次状态变化自动更新。
- **BD 名出现在标签上不等于归属这个 BD**，是否归属只看后缀。
- **公共池达人不显示归属标签**（从未被触达、保护期已过、原 BD 离职，都不显示）。

| 情况 | 标签示例 | 是否归属该 BD |
|---|---|---|
| 已建联成功、保护期内 | `林丽洪·已归属（至12/20）` | 是 |
| 已触达、达人未回复 | `李汝华·未回复（冷却至11/30）` | **否**（只是记录谁最近联系过） |
| 冷却期已过、仍未回复 | `李汝华·未回复` | 否 |
| 存在未判定的冲突 | `林丽洪/林乐欣·冲突待判`（列出**所有**冲突 BD） | 待负责人判定 |
| 公共池（从未触达 / 保护已过 / 原 BD 离职） | 不显示 | 否 |

- 多个 BD 先后触达、达人都未回复 → 标签显示**最近一次触达**的 BD（与 §3.5「回复归最近一次触达的 BD」一致）。
- 「未回复」标签什么时候消失：建议在最近一次触达满 90 天后不再显示，达人回到无标签状态。（默认，见 §10）
- 定向计划有效期（§3.2）不进标签，在达人档案里单独显示。
- 纠错只能走「冲突 / 归因审查 → 负责人判定」，留下原因和记录。

**② 群发标签（下行，可自定义）**
- BD 在插件里自定义（如 `AR141新品`、`高潜`、`泰语`），用于在聊天界面的达人列表里筛选和分组群发；相当于原灵途「达人360标记」。
- **每个 BD 各自一套，只在本人账号显示**，别人看不到。
- 现状存在插件本地；以后改存本系统（按账号保存），换电脑、重装插件不会丢。
- 显示在聊天界面的达人列表中；**不参与任何归属判定**。

### 8.2 BD 每日建议清单
- 候选范围：自己保护中的达人、公共池达人；**不含别人保护中的达人**。
- 分组按以下优先级排列，组内按近 90 天 GMV 从高到低：
  1. 达人已回复待处理
  2. 保护期剩 ≤15 天
  3. 近 30 天有出单但 ≥14 天没联系
  4. 发样 ≥10 天未回收
  5. 已接受计划未申样 / 申样待处理
  6. 冷却期已满可以再触达
  7. 公共池高出单达人
- 每天最多显示 30 条。（参数为默认值，可配置，见 §10）

### 8.3 BD 冲突列表 / 管理员每日看板
- 按业务逻辑梳理 §7.4、§7.5 实现：发样数、回收数、群发与定向的任务数和达人数、名额使用、冲突数等。
- 冷却和认领统计要**包含插件回传的群发**。

## 10. 按建议默认、负责人未逐条确认的点（开发照此实现，可配置，负责人可随时改）

1. 同一会话内的人工跟进不算新触达，不受 14 天限制（§2）。
2. **已确认（v1.2）**：达人的普通回复暂不续期（跟进权、GMV 两层都不续），系统搭建完成后再完善（§3.3）。
3. 回复归会话中最近一次触达的 BD（§3.5）——**已确认**；申样归来源定向计划的发起人（§3.6）——默认。
4. 外部渠道登记带截图且达人有回复 → 直接记为建联成功，发生冲突再判（§6.1）。
5. 插件群发前预检，并拦截不可发的达人（§6.2）。
6. 每日清单参数：保护期剩 15 天提醒、14 天没联系算近期未联系、发样 10 天未回收、近 30 天有出单、每天最多 30 条（§8.2）。
7. 冲突通知：保护期内他人动作、VID 重复即时通知，其余每日汇总（§5）。
8. 飞书建联表同步维持每晚一次（T+1）。
9. 「未回复」归属标签在最近一次触达满 90 天后消失（§8.1）。
